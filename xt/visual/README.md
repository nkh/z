# Visual Regression Tests

Automated screenshot-based regression tests for Gtk3::SourceEditor.

## Overview

Each test launches a headless GTK editor widget, takes a PNG screenshot,
and compares it against a golden reference image.  Tests are driven by
Perl macros that configure the editor, optionally inject keystrokes, and
capture snapshots.

## Files

```
xt/visual/
  run_visual_tests.pl     Test runner (orchestrates child processes)
  snapshot_editor.pl      Child process (creates editor, runs macro, captures PNG)
  macros/                 Test macro files (one per test)
  golden/                 Golden reference images (generated by --init)
  output/                 Latest test output (overwritten each run)
  diffs/                  Diff images (generated on failure with --generate-diff)
```

## Running Tests

```bash
# Create/update all golden images
perl xt/visual/run_visual_tests.pl --init

# Create golden images only for tests that don't have one yet
perl xt/visual/run_visual_tests.pl --init-missing

# Run all tests against golden images
perl xt/visual/run_visual_tests.pl

# Run a single test
perl xt/visual/run_visual_tests.pl --target visual_dark_theme

# Run with diff image generation on failure
perl xt/visual/run_visual_tests.pl --generate-diff

# List all test names
perl xt/visual/run_visual_tests.pl --list

# Show GTK warnings from child processes
perl xt/visual/run_visual_tests.pl --verbose
```

The script exits 0 if all tests pass, 1 on any failure.

## How It Works

1. `run_visual_tests.pl` iterates over the test definitions (hardcoded
   in the `@tests` array) and for each test spawns `snapshot_editor.pl`
   as a child process.

2. `snapshot_editor.pl` creates a `Gtk3::SourceEditor` widget in an
   off-screen window, loads the test macro, waits for a startup delay
   (default 500ms), then runs the macro.  The macro calls
   `$ctx->snapshot()` which uses the editor's `snapshot()` method to
   render the widget to a PNG file.

3. The runner compares the output PNG against the golden image using
   pixel-by-pixel comparison with a configurable threshold (default 1%).

## Test Types

### Static tests (single snapshot)
Take one screenshot of the editor displaying content with specific options.
Used for themes, syntax highlighting, and editor configuration testing.

### Action tests (two snapshots)
Take a "before" screenshot, inject keystrokes via the macro, then take an
"after" screenshot.  Used to verify that editor actions (search, selection,
delete, yank/paste, etc.) produce the correct visual result.

## Macros

Each test has a corresponding macro file in `xt/visual/macros/`.  Macros
are Perl scripts that return a code reference:

```perl
# Static test: just take a snapshot
sub { my ($ctx) = @_; $ctx->snapshot() }

# Action test: snapshot, inject keystrokes, snapshot again
sub {
    my ($ctx) = @_;
    $ctx->snapshot('1');        # saves <name>_1.png
    $ctx->keys('v$');           # enter visual mode, go to end of line
    $ctx->snapshot('2');        # saves <name>_2.png
}
```

### Macro Context API (`$ctx`)

| Method | Description |
|--------|-------------|
| `editor()` | Returns the Gtk3::SourceEditor instance |
| `text()` | Returns full buffer text |
| `mode()` | Returns current vim mode string |
| `snapshot($label?)` | Capture PNG to output dir |
| `key($name)` | Press a named GDK key (e.g. 'Return', 'Escape') |
| `type($text)` | Type each character individually |
| `keys($sequence)` | Parse escape sequences and press keys |
| `ex($command)` | Enter command mode, type command, press Enter |
| `delay($ms)` | Wait N milliseconds (processes GTK events) |

### Macro File Naming

Macro filenames must match the test `name` field exactly:
- Test `visual_dark_theme` uses `macros/visual_dark_theme`
- Test `visual_char_selection` uses `macros/visual_char_selection`

## Debugging

### Timing editor startup

Pass `--debug` to `snapshot_editor.pl` to print millisecond-precision
timing of each construction phase:

```bash
perl xt/visual/snapshot_editor.pl --debug --macro xt/visual/macros/visual_dark_theme --macro-run visual_dark_theme --snapshot-dir .
```

This prints timestamps for: script start, theme loading, buffer creation,
widget assembly, vim bindings, and show_all.

### Diff images

When a test fails and `--generate-diff` is passed, a diff PNG is saved to
`xt/visual/diffs/`.  The diff image shows the golden image with differing
pixels highlighted in magenta (60% blend).  The absolute path is printed in
the test output.

### Interactive mode

Run `snapshot_editor.pl` without `--macro` or `--snapshot` to get an
interactive GTK window for manual testing.

## Golden Images

Golden images are not tracked in git (they are environment-specific).
After any change that affects rendering (theme changes, font changes,
snapshot method changes), regenerate them with `--init`.

Each golden image has a companion `.txt` description file explaining what
the test checks and what to verify visually.
